# i18n — internationalization

Zylara ships three interface languages:

| Code | Native name | Notes |
|---|---|---|
| `en` | English | Default for fresh installations and fallback catalog. |
| `pt-BR` | Português (Brasil) | Existing users keep it through the persisted `settings.locale`. |
| `es` | Español | Neutral Spanish. |

`Settings.locale` (backend) is the source of truth. `localStorage['zylara.locale']`
is only an anti-flash cache for the first paint. The model is instructed to
answer in the active interface language (unless the user writes in another
language).

## Architecture

- Renderer: `i18next` + `react-i18next`, bundled catalogs in
  `src/locales/{en,pt-BR,es}/<namespace>.json`. Runtime in `src/lib/i18n`.
  Components use `useTranslation('<namespace>')`; stores/helpers import `t`.
  Dates/numbers use `src/lib/i18n/format.ts` (never hardcoded `'pt-BR'`).
- Backend: `src-tauri/src/i18n.rs` with flat catalogs in
  `src-tauri/locales/{en,pt-BR,es}.json`. App-authored user-facing messages,
  approvals, defaults, installer copy and prompts use `t`/`t_args`/`t_count`.
  Raw provider bodies, subprocess output, file content, prompts/tool guidance
  and logs are not localized.
- Prompts: `harness/prompt.rs` and `harness/code/prompt.rs` read the locale's
  `prompt_name`; prompt snapshots include the locale in their config hash, so
  switching language invalidates the frozen snapshot.

## Adding a language

1. Copy `src/locales/en/` to `src/locales/<code>/` and translate every value.
2. Add the locale object to `src/locales/<code>/` imports/resources in
   `src/lib/i18n/resources.ts`.
3. Add an entry to `SUPPORTED_LANGUAGES` in `src/lib/i18n/languages.ts`
   (`AppLocale` is derived from it; do not edit `types.ts`).
4. Copy `src-tauri/locales/en.json` to `src-tauri/locales/<code>.json` and
   translate it.
5. Add a `LanguageMeta` entry to `LANGUAGES` in `src-tauri/src/i18n.rs`
   (`code`, `prompt_name`, `date_pattern`, `accept_language`).
6. Run:

```bash
pnpm i18n:check
pnpm typecheck
pnpm test
cd src-tauri && cargo test --lib
```

No component changes are required. `pnpm i18n:check` enforces key/placeholder
parity, registry consistency, Rust key literals and the absence of hardcoded
UI copy (allowlist: `scripts/i18n-allowlist.json`).

## Translation rules

- Translate the whole sentence; never concatenate fragments. Use named
  interpolation (`{{count}}`, `{{name}}`).
- Use plural keys `_one`/`_other` (backend `.one`/`.other`; `t_count` also
  supports `.zero`). Never use translated text as an id/sentinel.
- `pt-BR` preserves the historical rendered copy; `en` is the source key
  shape; `es` is neutral Spanish (tú in descriptions, infinitive buttons).
- Do not translate product/model/tool names, URLs, code, protocol tokens
  (`[arquivo: caminho]`, `/commands`) or user content.
